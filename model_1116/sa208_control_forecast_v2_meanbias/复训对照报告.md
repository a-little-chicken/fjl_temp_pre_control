# v2 Mean-Bias 锚定复训报告

**结论：复训完成；指标有局部改善，但仍远未达到准入，不可用于现场控制。** 本轮只读使用 sa-208 现有 CSV，在 GPU1 离线训练；未访问 IOT、未写现场、未下发动作。

## 1. 本次变更与验证

按本地更新的 `control_forecast.py`，LPV scheduler 最后一层权重/偏置零初始化，使初始化调制输出为零、K 与 τ 从先验中心出发；轨迹 Loss 新增 `0.2 × (预测与真实温度增量轨迹均值差)^2`。该项进入 Stage 2 的 `loss_fn.total`，Stage 1 仍使用其既定的 `far_huber + 2*amplitude + 5*prior_loss` 目标。

本地与 sa-208 单测均通过（12 项）。训练数据、时间折和模型超参数与 v2 首轮一致；训练 4 轮 Stage 1、12 轮 Stage 2。最佳权重按 Oracle 验证加权 RMSE 选择。相同验证窗口共 3,302 个。

## 2. 与 v2 首轮对照

所有主要预测值均为**未来真实尾煤输入的 Oracle 条件回放**，不是在线预测。表中 per-window mean error 由保存的逐样本轨迹计算，衡量每个 15 分钟窗口内误差的均值。

| 指标 | v2 首轮 | Mean-Bias 复训 | 变化 |
|---|---:|---:|---:|
| Oracle 加权轨迹 RMSE | 32.93℃ | **32.24℃** | −0.70℃ |
| Oracle 端点 RMSE | 39.41℃ | **38.74℃** | −0.67℃ |
| Oracle 全点绝对误差 P90 | 50.69℃ | **49.27℃** | −1.42℃ |
| 最大时距平均偏差（逐预测时刻） | 24.33℃ | **26.25℃** | +1.92℃，变差 |
| 每窗口平均误差 MAE | 14.66℃ | **13.71℃** | 改善约 6.5% |
| 每窗口平均误差 RMSE | 19.98℃ | **18.84℃** | 改善约 5.7% |
| 全验证点总体误差偏置 | −4.98℃ | **−0.63℃** | 更接近零 |
| 平均预测/真实峰峰值 | 50.43 / 56.73℃ | **48.46 / 56.73℃** | 振幅比 0.854 |
| 峰/谷 MAE（当前初步 KPI） | 15.21℃ | **15.39℃** | 略变差 |
| 拐点时间 MAE | 4.03 步 | **3.59 步** | 仍高于 2 步 |

“每窗口均值误差”及全局偏置改善，说明 mean-bias 项对其直接优化的统计量有一定帮助；但逐时刻最大平均偏差反而上升，因此不能声称它从数学上消除了远端漂移。加权 RMSE、端点、P90 的改善较小，远未达到 8℃、10℃、15℃、2℃的参考准入线。

## 3. 其他诊断

- 保持当前煤量的历史标签诊断：加权 RMSE 26.68℃、端点 31.12℃、P90 40.75℃。真实历史未来煤量并非保持不变，此项不是有效反事实，也不是部署成绩。
- 虚拟未来尾煤 ±2 t/h：端点受迫响应约 +14.36℃ / −14.36℃，符号正确，单调比例均为 1.0；LPV 参数仍为 `K=7.5` 下限、`τ≈280s` 上限，说明边界退化未解决。此测试仅核查公式行为，不是物理响应证据。
- `turn_miss_fraction` 的实现并非一对一事件匹配；红线 MAE 也只是越阈值点误差，不能作为严格峰谷事件验收。

## 4. 判断与产物

均值锚定改善了窗口整体电平偏差，但不能替代更严格的时距误差控制；P2P、极值和相位也没有同时改善。该模型不准入，不得用于候选动作优化或闭环控制。未来真实煤量仍只能作为离线 Oracle 变量；Stage 1/LPV 拟合仍不构成因果辨识。
